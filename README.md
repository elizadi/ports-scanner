# tcpPortsScanner

Go-пакет для проверки доступности TCP-портов на одном или нескольких хостах
методом обычного TCP Connect. Без CLI, HTTP, БД и брокеров — только библиотека.

- Только стандартная библиотека, сторонних зависимостей нет.
- Go 1.25.5 (`go.mod`).
- Нет глобального изменяемого состояния, `Scanner` потокобезопасен.
- Не реализовано (по условию): SYN/UDP-сканирование, raw sockets, определение ОС,
  обход фаерволов, эксплуатация уязвимостей.


## Использование

```go
scanner, err := portscan.New(
    portscan.WithConcurrency(100),
    portscan.WithConnectTimeout(500*time.Millisecond),
)
if err != nil {
    return err
}

results, err := scanner.Scan(
    ctx,
    []string{"192.168.1.10", "example.org", "::1"},
    portscan.Merge(portscan.Range(1, 1000), portscan.Port(8080)),
)
if err != nil {
    return err // неверные аргументы, сканирование не начиналось
}

for r := range results {
    fmt.Printf("%s:%d %s\n", r.Host, r.Port, r.State)
}
```

`ScanAll(ctx, hosts, ports)` делает то же самое, но возвращает срез результатов.

## Публичный API

| Сущность | Назначение |
|---|---|
| `New(opts ...Option) (*Scanner, error)` | создаёт сканер |
| `(*Scanner).Scan(ctx, hosts, ports) (<-chan Result, error)` | потоковое сканирование |
| `(*Scanner).ScanAll(ctx, hosts, ports) ([]Result, error)` | результаты одним срезом |
| `Port`, `Ports`, `Range`, `Merge` → `PortSet` | построение набора портов |
| `Result` | `Host, IP, Port, State, Duration, Err` |
| `State` | `StateOpen, StateClosed, StateTimeout, StateUnreachable, StateCanceled, StateError` |
| `WithConcurrency(n)` | максимум одновременных подключений на весь `Scanner`, суммарно по всем `Scan` (по умолчанию 100) |
| `WithConnectTimeout(d)` | таймаут подключения (по умолчанию 1s) |
| `WithResolveTimeout(d)` | таймаут разрешения одного DNS-имени (по умолчанию 5s) |
| `WithResolveConcurrency(n)` | сколько DNS-имён разрешается одновременно (по умолчанию 8) |
| `WithResolver`, `WithDialFunc` | подмена DNS и подключения (прокси, тесты) |

Ошибки-значения: `ErrNoTargets`, `ErrEmptyHost`, `ErrInvalidHost`, `ErrResolve`,
`ErrNoPorts`, `ErrInvalidPort`, `ErrReversedRange`, `ErrInvalidOption`, `ErrNilContext`.
Проверяйте их через `errors.Is`.

## Поведение

**Цели.** Принимаются IPv4, IPv6 (в том числе `[::1]`) и DNS-имена. Хосты
проверяются до запуска. Некорректные не отменяют скан: по каждому приходит один
`Result` с ошибкой, остальные хосты сканируются как обычно.

| Случай | Поведение |
|---|---|
| пустой список хостов | ошибка `Scan`: `ErrNoTargets` |
| пустой хост | не ошибка `Scan`: один `Result` с `Port == 0`, `State == StateError`, `errors.Is(Err, ErrEmptyHost)` |
| некорректный адрес (`999.1.1.1`, `host:80`, пробелы, не-ASCII) | то же, с `errors.Is(Err, ErrInvalidHost)` (IDN — только punycode) |
| неразрешимое DNS-имя | не ошибка `Scan`: один `Result` с `Port == 0`, `State == StateError`, `errors.Is(Err, ErrResolve)`; остальные цели сканируются |
| повторяющиеся цели | каждый уникальный IP сканируется один раз (имена сравниваются без учёта регистра; `example.org.` и `example.org` — разные цели, но если они разрешились в одни адреса, повторно адреса не сканируются). Если все адреса имени уже проверены под другим именем, для него результатов не будет |
| имя с несколькими IP | сканируются все адреса, `Host` общий, `IP` разный |

**Порты.** Дубликаты убираются, порядок сканирования — по возрастанию.

| Случай | Поведение |
|---|---|
| порт `0` или `> 65535` | `ErrInvalidPort` |
| обратный диапазон `Range(1000, 1)` | `ErrReversedRange` |
| пустой набор | `ErrNoPorts` |

**Состояния** определяются по типам ошибок и errno (`errors.Is` / `errors.As`),
текст ошибки не анализируется. Исходная ошибка лежит в `Result.Err`.

| Состояние | Условие |
|---|---|
| `open` | соединение установлено (сразу закрывается) |
| `closed` | `ECONNREFUSED` (на Windows — `WSAECONNREFUSED`) |
| `timeout` | истёк таймаут подключения |
| `unreachable` | `ENETUNREACH`, `EHOSTUNREACH` (на Windows — `WSAENETUNREACH`, `WSAEHOSTUNREACH`) |
| `canceled` | отменён `ctx` |
| `error` | всё остальное |

**Конкурентность и отмена.**
- Одновременных подключений не больше `WithConcurrency(n)`. Лимит общий для всего
  `Scanner`: несколько параллельных `Scan` делят его между собой.
- Лимит дескрипторов ОС (`ulimit -n`) нужно учитывать самостоятельно: при слишком
  большом `n` часть проверок вернёт `StateError` (например, «too many open files»).
- Задания выдаются по одному, память не зависит от числа целей × портов.
- Канал нужно читать до закрытия или отменить `ctx`. Пока канал не читают,
  новые подключения не открываются.
- После отмены новые задания не выдаются, запущенные подключения прерываются
  (по возможности возвращаются как `canceled`), канал закрывается.
- `Scanner` можно использовать повторно и из нескольких горутин.
- `ScanAll` возвращает `ctx.Err()` только если отмена реально прервала сканирование;
  если оно успело завершиться полностью, ошибки нет.

## Ограничения

- Только TCP Connect; сервисы и ОС не определяются.
- Порядок результатов не гарантируется.
- DNS-имена разрешаются параллельно (до `WithResolveConcurrency`, по умолчанию 8), каждое — с таймаутом `WithResolveTimeout`; порядок обработки целей сохраняется.
  Для тысяч имён лучше заранее разрешить их самостоятельно и передать IP.
- У `Result.IP` нет zone IPv6 (`fe80::1%eth0`); для явно заданного адреса она
  сохраняется в `Result.Host`.
- CIDR не поддерживается.
- Нет ограничения скорости (rate limit): подключения к одному хосту идут столько
  параллельно, сколько позволяет `WithConcurrency`. Такое сканирование может
  срабатывать на системах обнаружения вторжений.
- Воркеры запускаются лениво (не больше `WithConcurrency`), буфер канала
  результатов ограничен 256 элементами, поэтому большое значение
  `WithConcurrency` само по себе память не расходует.

## Разработка

```sh
go vet ./...
go test -race ./...
```

Тестам не нужна внешняя сеть: сеть и DNS подменяются через `WithDialFunc` и
`WithResolver`, реальные подключения идут только на loopback.
